## 2024-05-15 - [Batch DOM insertions with DocumentFragment]
**Learning:** Found a common performance anti-pattern across `app.js` and `features.js` where DOM elements were being directly appended to live containers (like `ticksGroup`, `svg`, `grid`) repeatedly inside loops (e.g. `for` and `forEach` loops for map markers, timeline cards, clock ticks, and chart points). This triggers excessive reflows and repaints, especially with SVGs and large lists, degrading rendering performance.
**Action:** Always initialize a `DocumentFragment` before a loop, append all newly created elements to the fragment within the loop, and then append the fragment to the live DOM node once at the end. This batches the layout updates into a single operation.
## 2024-05-16 - [Throttle heavy SVG renders in pointer events]
**Learning:** Found a performance bottleneck where complex layout rendering (the 3D / 2D interactive SVG map) was being triggered synchronously on every `pointermove` event. This was firing far faster than the browser's refresh rate (e.g. 60+ Hz), causing excessive layout thrashing and degrading interactivity.
**Action:** Always decouple high-frequency input events (`pointermove`, `scroll`) from heavy rendering logic (like `drawWorldMap`). Use `requestAnimationFrame` with a pending frame flag (e.g. `dragRafId`) to throttle rendering so it only executes when the browser is ready for the next frame.
## 2024-05-17 - [Debounce input events triggering heavy DOM updates]
**Learning:** Found a performance issue where the timeline search input (`initTimelineArchiveSearch`) was triggering `renderTimelineCards` on every keystroke. Because `renderTimelineCards` creates and appends many DOM elements inside a loop, executing it on every keystroke blocks the main thread, causing lag and jank during typing.
**Action:** Debounce high-frequency input events (e.g. search inputs) by wrapping the expensive callback in a `setTimeout` (e.g., 300ms) and clearing the previous timer on each new input. This ensures the heavy DOM update only occurs once after the user stops typing.
